# MiniMax-H3 on Google Cloud TPU with SGLang

This repository contains serving recipes, benchmark results and generated videos for **MiniMax-H3** (video generation with synchronized stereo audio). The primary platform is **Google Cloud TPU v7x (Ironwood)**, with additional results on **TPU v5p**. The model is served with SGLang on TorchTPU (`sglang-torchtpu`) on Google Kubernetes Engine (GKE).

Every latency result links to the MP4 generated by that run, so you can review video and audio quality alongside performance.

## How results are reported

| Item | Definition |
| :--- | :--- |
| **Latency metric** | `inference_time_s`, as reported by the SGLang server. This is the server-side net inference segment of one request, from pipeline start through the decoded video frames and audio. It excludes HTTP transport, queueing, input download and MP4 muxing. End-to-end client time is reported separately in [`BENCHMARK_RESULTS.md`](BENCHMARK_RESULTS.md). |
| **Method** | Warm server, one request at a time (`concurrency = 1`). After a warm-up request, the identical request (same prompt, inputs and seed) is repeated. We report the median of the repeated requests and list each run. |
| **Hardware unit** | One TPU v7x host has 4 chips: 8 TensorCores and 768 GiB of HBM. |
| **Attention and sampling** | Dense attention and no step caching (`cache_dit` off) throughout. Flow shift is the model default (12.0 video / 3.0 audio) unless a table states otherwise. |
| **Outputs** | H.264 video at 24 fps with 32 kHz stereo AAC audio, stored in [`videos/`](videos/). |

**Notes:**
- **"Online FP8"** quantizes the DiT linear layers to FP8 when the server starts. Attention and normalization stay in BF16. When a Turbo LoRA is used, it is merged into the BF16 weights before quantization.
- **"BF16 (lossless)"** is the official 50-step checkpoint in BF16/FP32 with dense attention, no LoRA and no quantization.
- **Row 5** was measured with device-synchronized stage profiling enabled. On the I2V workload this mode changes `inference_time_s` by less than 0.1%: 68.046 s profiled vs 68.100 s unprofiled.
- **Row 6** is a single warm request: the identical 50-step request, repeated once after the first request.

The exact request parameters, prompts, input checksums, model revision and adapter files for each workload are listed in [Workload specifications](BENCHMARK_RESULTS.md#2-workload-specifications). That section also has end-to-end times, cold-start compile times, memory and per-stage latency breakdowns.

## Hardware and serving stack

| Component | Configuration |
| :--- | :--- |
| **Accelerator** | Cloud TPU v7x (Ironwood), `tpu7x-standard-4t`: 4 chips, 8 TensorCores and 768 GiB HBM per host (96 GiB per TensorCore). Also Cloud TPU v5p, `ct5p-hightpu-4t`: 4 chips per host. |
| **Topologies** | v7x: 1 host (4 chips) for per-request latency; 2 hosts (8 chips) and 4 hosts (16 chips) for multi-replica throughput. v5p: 1 host (4 chips). |
| **Orchestration** | Google Kubernetes Engine (GKE), with model checkpoints in Cloud Storage. |
| **Serving runtime** | `sglang-torchtpu` (TorchTPU 0.2.0, libtpu 0.0.50, JAX 0.11.2). |
| **Parallelism** | Ulysses sequence parallelism across the 8 TensorCores of a v7x host (`--num-gpus=8 --ulysses-degree=8`; MiniMax-H3 has 56 attention heads, so 7 heads per core). Encoders are sharded with `--encoder-parallel=fold`. |
| **Attention kernel** | Dense Pallas Splash Attention (`--attention-backend=tpu_splash_attn`). |
| **Precision** | Online FP8 (`--quantization=fp8`) on DiT linear layers, or unquantized BF16/FP32. |
| **Media encoding** | A separate CPU service (`video-encode-svc`) muxes H.264 (24 fps) and stereo AAC (32 kHz) into MP4. |

## Deploy and benchmark on GKE

### 1. Create a TPU v7x node pool

```bash
export PROJECT_ID=<YOUR_PROJECT_ID>
export REGION=<YOUR_REGION>
export ZONE=<YOUR_ZONE>
export CLUSTER_NAME=<YOUR_CLUSTER_NAME>
export NODEPOOL_NAME=<YOUR_NODEPOOL_NAME>
export GCS_BUCKET=<YOUR_GCS_BUCKET>

gcloud container node-pools create ${NODEPOOL_NAME} \
  --project=${PROJECT_ID} \
  --location=${REGION} \
  --node-locations=${ZONE} \
  --num-nodes=1 \
  --machine-type=tpu7x-standard-4t \
  --workload-metadata=GKE_METADATA \
  --cluster=${CLUSTER_NAME}
```

### 2. Stage model checkpoints in Cloud Storage

```bash
hf download MiniMaxAI/MiniMax-H3 --revision 42ed227ee7df40d41602854ae760620d6eb651fe --local-dir ./MiniMax-H3
hf download lightx2v/Minimax-h3-Turbo --local-dir ./Minimax-h3-Turbo
gcloud storage cp -r ./MiniMax-H3 gs://${GCS_BUCKET}/models/MiniMaxAI/MiniMax-H3
gcloud storage cp -r ./Minimax-h3-Turbo gs://${GCS_BUCKET}/models/lightx2v/Minimax-h3-Turbo
```

### 3. Deploy the SGLang server and the CPU MP4 encoder

First, update `<YOUR_GCS_BUCKET>` and `<YOUR_ARTIFACT_REGISTRY>` in [`k8s/sglang-minimax-h3-server.yaml`](k8s/sglang-minimax-h3-server.yaml). Then deploy:

```bash
gcloud container clusters get-credentials ${CLUSTER_NAME} --location=${REGION} --project=${PROJECT_ID}
kubectl apply -f k8s/video-encode-svc.yaml
kubectl apply -f k8s/sglang-minimax-h3-server.yaml
kubectl logs -f deployment/sglang-minimax-h3-tpu
```

Submit a request:

```bash
kubectl port-forward service/sglang-minimax-h3-service 30010:30010

curl -X POST http://localhost:30010/v1/videos \
  -H 'Content-Type: application/json' \
  -d '{
    "prompt": "At night, while their owner sleeps in a bedroom, three cats march in loudly playing tiny brass instruments, then abruptly file out.",
    "size": "1344x768",
    "duration": 5,
    "fps": 24,
    "num_inference_steps": 50,
    "seed": 1101
  }'
```

### 4. Run the benchmark jobs

```bash
# Single-host latency and stage profiling (four independent 1-host v7x nodes)
kubectl apply -f k8s/minimax-h3-v7x-single-host.yaml

# Multi-host throughput (2 hosts = 8 chips, 4 hosts = 16 chips) and TPU v5p
kubectl apply -f k8s/minimax-h3-v7x-8.yaml
kubectl apply -f k8s/minimax-h3-v7x-16.yaml
kubectl apply -f k8s/minimax-h3-v5p-16.yaml
```
